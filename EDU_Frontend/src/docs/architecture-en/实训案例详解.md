# Lab Case Study - K8S Classic Lab Project Practice

Course labs and project practice now use one runtime: K8S Classic Lab. Students enter `/lab` from a lesson or project unit, work in an isolated environment, follow the Agent manual, run verification, and submit evidence for teacher review.

## Student flow

```text
Learning center or project list
  -> lesson / project detail and unit
  -> create or reuse a Lab session
  -> noVNC desktop / web app / terminal
  -> Agent step verification
  -> assignment submission and feedback
  -> stop the environment or wait for TTL cleanup
```

Projects are no longer routed to different runtimes by tag or type. Every publishable project uses an environment image or an active Lab template and enters `/lab`.

## Runtime model

For each active session, the Go backend creates runtime resources in the K8S namespace:

- A main Lab Pod, optionally with an IDE container.
- A ClusterIP Service reachable only through the platform proxy.
- noVNC desktop, template web applications, and a K8S exec terminal.
- Expiration, quota, runtime-event, and audit records.

The browser never receives raw node ports. Desktop and web applications use `/api/lab/proxy/*`, while the terminal uses `/ws/terminal` as a K8S exec bridge.

## Agent verification

Agent manuals organize content, quick questions, and verification rules into steps. Verification runs through `/api/lab/execute` in the student's owned session, so the browser cannot forge the result.

Supported rule families include `file_exists`, `command_output`, `service_running`, and controlled `custom` scripts.

## Capacity and cleanup

- Session creation resolves user, class, and global quotas.
- Reaching the concurrent-session limit returns an actionable error.
- Stopping a session deletes its Pod and Service idempotently.
- The janitor checks expired sessions and orphan resources every 30 seconds.
- Administrators can inspect sessions, logs, events, and stop requests from the Dashboard.

## Acceptance

1. Published projects are visible; draft and archived projects are not.
2. Project details and units enter `/lab`.
3. `create / active / noVNC / terminal / execute / stop` works end to end.
4. Agent verification operates only on the student's owned active session.
5. Submission, grading, return, resubmission, and grade publication form a closed workflow.
6. Expired or abnormal resources are reclaimed by the janitor and operations controls.
