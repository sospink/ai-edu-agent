# Core Concepts

The current Agent EDU Lab architecture combines course content, real runtime environments, teaching agents, and three-portal governance.

## Three Portals

| Portal | Entry | Responsibilities |
| --- | --- | --- |
| Student | `/study`, `/projects`, `/lab`, `/openclaw/*` | Learning, labs, submissions, feedback |
| Teacher | `/teacher/*` | Classes, content, assignments, grading, gradebook, Agent observability |
| Admin | `/admin/*` | Users, content governance, K8S operations, quotas, audit, settings |

## Main Go Backend

`EDU_Backend_Go/` is the current main backend. It uses Gin, GORM, MySQL, Casbin, and JWT. Routes are registered in `internal/router/router.go`, and business logic is organized by domains such as `auth`, `user`, `course`, `project`, `learning`, `lab`, `agent`, `openclawview`, `classroom`, `publishing`, `assignment`, and `operations`.

The TypeScript backend `EDU_Backend/` remains in the repository, but it is not the default place for new work.

## Classic Lab

Classic Lab is the real runtime used by lessons and normal project units. It is managed by the Go backend on K8S:

```text
Create lab
→ Resolve course / project / assignment resources
→ Check lab templates and quotas
→ Create K8S Pod / Service
→ Expose noVNC, gateway, and terminal URLs
→ Execute validation through K8S exec
→ Stop or clean up through janitor and write audit logs
```

`/api/docker/*` is legacy and is not the current main runtime.

## OpenClaw

OpenClaw is an independent project scenario flow. Projects must carry the `OpenClaw` tag, and students enter `/openclaw/*` from project details. The backend `openclaw-view` domain maintains phase views, messages, files, and integration with OpenClaw Gateway and Feishu.

OpenClaw does not create a Classic Lab session first, and the frontend must not forge `agent:*` session keys.

## Agent Manuals and Teaching Observability

Agent manuals split lessons or project units into guided steps. Steps may include instructions, quick questions, verification rules, and AI suggestions. Students use them for guided practice. Teachers use the Agent observatory to inspect step heatmaps, blockers, chats, terminal evidence, FAQs, and intervention records.

## Publish Checks

Courses, projects, and Agent manuals go through publish checks before becoming visible. Checks cover content completeness, Agent verification, Lab templates, OpenClaw tags, and other gates. Results are written to publish audit logs.

## Learning Overview

`/api/learning/overview` aggregates course progress, lesson completion, streaks, assignments, and Agent step progress. It feeds the top cards on `/study` and the level card in the profile page. It is the first version of learning outcome tracking, not a certificate or badge system.

## AI Assistance

AI powers Agent Q&A, code explanation, validation suggestions, teacher feedback drafts, assignment summaries, and weak-point diagnosis. Teacher-side AI output usually requires teacher confirmation and does not replace grading.
