# 提示词工作台前端

独立 React + TypeScript + Vite 课程项目。默认中文，顶部可切换英文。所有业务数据通过课程 FastAPI 获取，不包含模拟模式、模型密钥或平台导航。

## 本地启动

```bash
npm ci
npm run dev
```

默认前端地址 http://127.0.0.1:5173，开发代理指向 http://127.0.0.1:8000。后端启动方式由课程目录的说明负责。生产运行 `npm run build`，FastAPI 提供 `dist/`。没有 BrowserRouter；资源和 API 使用相对路径以适配以 `/` 结尾的 Lab 子路径入口。

## 检查

```bash
npm run typecheck
npm run build
npm test
```

浏览器测试使用 Playwright Chromium（首次运行可执行 `npx playwright install chromium`）。测试通过请求拦截验证接口契约与交互，不可代替真实模型与平台 Lab 的端到端验收。截图输出在 `.artifacts/`，不提交。测试服务器使用 5179，不复用其他进程。

也可使用已安装的 Chrome：`PLAYWRIGHT_CHANNEL=chrome npm test`。运行真实后端验证时，先在 8000 启动课程后端，再执行 `LIVE_BACKEND=1 PLAYWRIGHT_CHANNEL=chrome npm test`。集成测试创建后删除带时间戳的草稿，不调用收费模型；需要使用测试数据库。

## 代码导读

- `src/types.ts`：课程 API 数据类型和提示词初始值。
- `src/api.ts`：相对路径请求、HTTP 错误和 ZIP 下载，不处理模型凭证。
- `src/locale.ts`：独立的 `workbench-language` 设置；全部 API（含导出）携带 `X-Locale` 和 `Accept-Language`（`zh-CN` / `en-US`），不读取主平台语言。
- `src/App.tsx`：工作区状态、读写操作、取消、确认和中英文。
- `src/components/Library.tsx`：样例、草稿、历史、搜索和对比选择。
- `src/components/Editor.tsx`：四段提示词和草稿名称。
- `src/components/Result.tsx`：原始响应、格式化 JSON、服务端结构与证据检查。
- `src/components/Compare.tsx`：两个历史实验的独立对照视图，标记提示词差异。
- `src/components/Overlay.tsx`：挂载到 body 的原生 dialog，提供焦点约束、Esc、滚动锁定和焦点返回。独立课程不引用平台组件及其构建依赖。
- `src/styles.css`：三栏桌面、双栏平板、纵向移动端与减少动态效果支持。

## 行为边界

- 草稿支持创建、覆盖编辑、删除；切换草稿或样例前确认未保存修改，离开页面触发浏览器保护。
- 运行用 `AbortController` 中止 fetch；上游取消及不写成功记录由后端实现。前端不会为取消或失败制造成功响应。
- 响应区的编辑仅用于本地复核，调用校验时使用该次实验的原始输入；不会篡改历史记录。
- 历史上限由契约限定为最近 100 条，在该集合内搜索和双记录比较；不虚构服务端分页。
- 导出下载服务端 ZIP；未保存提示词和响应修改不会进入导出，操作前会确认。
- 校验只展示服务端可验证的结构与原文证据结论；服务和症状的语义需要人工复核。
- 界面语言切换重新拉取后端样例与配置；不会修改已载入的学生提示词、草稿名称、参数、模型响应、校验或对比选择。查看历史或重新校验时采用当前语言请求。快速切换会取消过期请求。
- 真实模型运行需要后端已配置 Lab 凭证；未配置时运行禁用，草稿与校验仍可使用。

## 真实后端浏览器验收路径

使用实际 Lab 地址或本地前端 `http://127.0.0.1:5173/`，后端需运行最新版本；禁用任何测试路由拦截。以下为人工验收步骤，不代表已执行真实模型调用。

1. 中文界面左侧「报障样例」点击「校园云盘上传失败」。原始报障应包含「今天14:20，教学楼A的校园云盘无法上传PDF，页面显示503。下载旧文件正常，换浏览器后仍然失败。」。另两份真实样例为「云实验桌面连接超时」「课程视频播放卡顿」。样例点击会载入默认提示词；已有未保存编辑时先显示确认。
2. 把草稿名称改为「浏览器验收 A」，点击顶部「保存」。修改任务指令但先不要保存，点击顶部语言按钮（中文时图标旁为 EN）。样例标题应变成 `Campus cloud drive upload failure`、`Cloud lab desktop connection timeout`、`Course video buffering`；编辑区仍保留刚才的中文内容和未保存状态。Network 中只新增 `samples`、`config` 读取，两者头部均为 `X-Locale: en-US`、`Accept-Language: en-US`。切回中文，确认编辑内容仍在。
3. 确认模型已配置且「运行」可用，点击「保存」再点击「运行」。等待右侧出现 LIVE、Request ID、响应及校验；记录本次 Request ID 与时间，作为 A。不要将测试夹具的 `test-request-*` 当成真实来源。
4. 保持相同原始报障，仅在任务指令末尾增加「请把未知信息列入 missing_fields，不推断任何故障原因。」；点击「保存」「运行」。记录第二次 Request ID 与时间，作为 B。两次都需成功才有两条可对比记录；失败或取消不能代替成功记录。
5. 左侧展开「运行历史」，找到最新两条。**勾选每行最左侧复选框**（点击行中文字仅查看单条详情），上方计数从「对比 0/2」变为「对比 2/2」。点击「对比 2/2」，打开独立「双记录对照」弹窗。A/B 顺序是勾选顺序；可先勾较早记录，再勾较新记录。
6. 核对弹窗两个 Request ID、原始输入、响应、耗时、Token 和校验，任务指令应标记「有差异」，相同输入不应标记差异。按 Esc 或右上角关闭回到原表单，两条选择保留。窄屏弹窗为纵向 A/B，向下滚动查看第二条。
7. 切到英文后点击 Export；若有未保存内容，点 Confirm。Network 中 `export` 同样应带两个英文语言头，下载 ZIP。可以在右侧响应中输入非法 JSON，再点击 Validate JSON，检查后端错误/校验消息使用当前语言且历史原记录未被修改。

记录验收证据时保留截图、两个真实 Request ID、实验时间、浏览器宽度及 Network 请求头；无需记录或展示模型凭证。若模型未配置，只能验收草稿、语言、校验与导出，双记录真实模型对照必须标为待验收。
