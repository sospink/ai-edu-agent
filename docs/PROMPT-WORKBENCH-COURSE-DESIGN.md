# 提示词工作台课程案例设计

本方案针对产品介绍第 4.6 节“大语言模型基础与应用实训”。学生围绕一套真实可运行的提示词工作台完成需求分析、提示词设计、模型调用、结构化校验、代码审查和成果交付。WebIDE、Desktop、Terminal、OpenCode CLI 与右侧 Agent 服务于同一项目，不再分别提供互不关联的演示页面。

本文件保留方案评估过程。2026-11-24 最新实施要求为两个小节：理论资料45分钟、完整实训105分钟，具体课表和操作以 `courses/prompt-workbench/README.md` 及实施记录为准；下文原“四课时”安排仅作为知识阶段参考。本方案不替代第二门部署与运维课程，也不将 4.7 的 K8S 发布与性能治理内容塞入 4.6。

## 一 课程定位

课程名称建议为“大语言模型基础与应用实训 提示词工作台开发”。案例产品是一套面向校园云服务运维的工单结构化工具：学生将服务报障原文输入工作台，编辑提示词，调用模型，检查工单字段与事实依据，并记录实验和审查结果。

保留提示词四要素的教学概念，但界面重新设计，不复刻截图布局。原附件的校园报修样例可作为入门数据，主实验采用校园云服务报障，例如“活动报名网站提交后显示 502，发生时间不详”。通过真实项目引导学生理解模型能力、不确定性、提示词和应用验证。

每门四课时、每课时 45 分钟只能支撑“提供可运行骨架，学生补全关键逻辑”的教学方式。假设学生能读简单 Python 和前端代码；若需从零学习 React、HTTP、Python，则必须另加预备课或增加课时。

## 二 案例产品的功能

### 2.1 四要素编辑区

包含指令、上下文、输入数据、输出要求四个编辑区，提供校园报修与云服务故障等脱敏样例。学生完善四要素后，工作台构建真实请求预览；缺项时给出具体字段反馈，避免空请求消耗模型额度。

示例输入为“校园活动报名网站提交信息后出现 502，其他页面能打开”。示例输出要求为 JSON，包含 `service`、`symptom`、`evidence`、`missing_fields`。要求原文没有的主机 IP、根因和时间不能被当成事实补出；缺失字段需明确列出。

### 2.2 请求与参数区

展示实际模型、允许调整的参数和最终请求体，不展示供应商密钥。支持一键运行、运行中状态、取消、失败重试和请求导出。

Temperature、Top_P、输出长度等参数依据课程允许的模型能力启用，不给所有模型固定放一套可编辑滑块。当前 Kimi 配置已通过基础文本和流式测试，但参数可调范围尚需专项验证。若模型不支持温度调节，温度控件只读并显示原因，将对照实验改为“固定模型和输入，仅改变提示词约束”。界面必须展示实际生效参数，不能以控件变化代替参数生效。

### 2.3 响应与校验区

分别展示模型原始文本、可解析 JSON、校验结果和当前错误。解析失败不能直接把补写后的内容标成原始响应。检查分成三层：JSON 是否有效、字段/枚举是否符合 Schema、关键事实是否有输入依据。

事实依据核对先限定为小范围、可判定任务，例如字段值出现在原文中、没有给缺失 IP 编造具体值、缺失字段列表符合要求；复杂语义交给人工复核，不宣称脚本能证明所有模型结论正确。

### 2.4 实验记录与对照区

保存输入、提示词版本、请求 ID、模型和配置版本、实际参数、响应、校验结果、耗时与时间。Token 使用量只有供应商实际返回时才显示；不伪造成本、耗时或 Token 数据。

支持将两个实验并排比较，要求学生说明唯一变更因素及结果差异。模型具有随机性，单次生成不能证明某种提示一定更好；课堂对照采用教师预设的少量固定样例，并保留失败结果。

### 2.5 审查与交付区

提供实验记录导出和成果清单。归档通过确定性脚本生成，包含源码、必要配置模板、实验记录、校验报告和人工复核说明；排除模型凭证、环境文件、依赖目录和临时文件。离线样例仅用于测试或接口不可用时的练习，必须明确标记，不作为真实模型调用验收证据。

## 三 五个入口的职责

| 入口 | 职责 | 可检查的结果 |
|---|---|---|
| WebIDE | 打开课程项目，编辑前后端代码、Schema、提示词模板和说明文件 | 实际文件修改和代码差异 |
| Desktop | 在主容器浏览器打开运行中的工作台，操作表单、请求、校验和对照功能 | 正常/异常交互及实际响应 |
| Terminal | 启动、构建、检查、测试和归档；查看应用日志 | 命令退出码、HTTP 响应、测试报告 |
| CLI OpenCode | 以当前项目为工作目录解释代码、审查改动、提出补丁，辅助完善交付说明 | 审查建议、采纳/拒绝理由、复测结果 |
| 右侧 Agent | 按当前手册步骤解释任务、提供分层提示、解释验证失败 | 步骤问答、验证与学习进度 |

右侧 Agent 是课程导师，OpenCode 是能读项目文件的开发助手。当前右侧 Agent 并不因此自动读取整个项目；需要源码时由学生提供最小片段或通过后续授权工具读取。不能在手册中暗示它已经审查了没有看到的文件。

课程接口建议为 `GET /api/health`、`GET /api/model-capabilities`、`POST /api/run`、`POST /api/validate`、`GET /api/experiments` 和 `GET /api/export`。这些是待开发的课程接口，不是当前平台已有路由。

首次进入即能启动骨架并看到页面。学生重点修改请求构造、Schema/校验规则、错误展示与实验记录等指定区域；通用路由、服务启动、模型凭证管理和导出安全逻辑由教师提供。

## 五 双容器与运行方式

WebIDE 和主容器位于同一 Pod，挂载同一个 `/workspace`。两者文件共享，但依赖和进程不共享。课程 Python、Node 和 OpenCode 在主镜像内统一准备；WebIDE 负责编辑，平台 Terminal 与 CLI 通过已有 K8S exec 在主容器运行。

所有入口使用明确的 `/workspace/prompt-workbench`，不依赖默认登录目录。当前 WebIDE 已默认打开 `/workspace`，学生可进入项目子目录；课程模式可进一步按受信任的课时配置自动打开对应子目录。Terminal 设置课程工作目录；OpenCode 启动时显式传入或切入该目录，已有 tmux 会话需按课程目录识别，避免复用到错误项目。该目录绑定能力仍需实现和验证，当前 CLI 仅启动 `opencode`。

推荐首期正式运行方式为：前端预构建，由 FastAPI 在 8000 端口同时提供静态页面和课程 API。学生修改前端后在 Terminal 执行构建并刷新 Desktop 浏览器，减少多个进程与代理配置给课堂带来的干扰。开发模式可选 Vite 5173 + API 8000；不要使用已被 WebIDE 占用的 3000。

Desktop 浏览器访问主容器的 `http://127.0.0.1:8000`。需要从平台应用入口直接访问时，通过 Lab 模板的应用端口代理开放，不新增学生应用的公网端口。前端资源路径和 API 路径需适配代理前缀；Desktop 的 localhost 可用不等于平台代理入口已验收。

镜像把课程模板放在 `/opt/courses/prompt-workbench`，首次会话初始化复制到 `/workspace/prompt-workbench`，已有项目不能被覆盖。依赖预装并锁定版本，不在课堂依赖临时联网安装。每个学生独立 Pod 和共享卷，互不覆盖；当前卷为 `emptyDir`，会话回收前必须导出或提交。

## 六 模型接入设计

平台助手、案例程序与 OpenCode 是三个调用方，不能因为管理端已经切换 Kimi，就认为三者全部接通。

建议新增受控教学模型网关，复用 Go 管理端的加密模型配置。网关绑定课程、学生与 Lab 会话，签发短时受限凭证，限制模型、并发、请求次数和输出长度；会话停止或到期后撤销权限。供应商 Key 只留在平台后端，不进入前端、课程源码、镜像或学生成果包。

案例后端通过这个网关发起教学请求。OpenCode 也使用课程专属网关配置，但必须单独验证消息历史、工具调用、工具结果与 SSE 兼容性。当前 Agent 的文本聊天接口不能直接充当完整的 OpenCode 兼容代理；首期若只完成文本接入，应明确 OpenCode 的在线审查仍未验收。

模型错误需要区分未配置、权限失败、额度不足、参数不支持、网络超时和响应不可解析。界面保留学生输入和已保存记录，不能在失败时自动生成一段假回答。多用户正式授课前，核对模型服务使用范围与额度；本次已有的 Kimi Code 配置不等同于取得无限课堂调用能力。

## 七 四课时教学设计

| 课时 | 任务 | 学生修改重点 | 验收证据 |
|---|---|---|---|
| 01 能力边界与任务分析 | 阅读业务样例、启动骨架、识别已知事实和缺失信息，查看项目结构 | 提示词模板、任务说明；用 WebIDE 阅读前后端入口 | 服务健康通过、需求分析、未编造字段的样例说明 |
| 02 提示词四要素与参数实验 | 补全请求构造，在 Desktop 运行真实请求，开展受控对照 | `buildRequest.ts` 中的请求组装、必填检查及允许的参数 | 请求预览与实际请求一致、真实 request ID、对照记录 |
| 03 结构化输出与 Python 校验 | 增加 Schema/事实依据检查，在页面展示错误；故意引入再修复问题 | `validators.py`、Schema 和错误展示区域 | 非 JSON、缺字段、错误字段等测试；失败与修复记录 |
| 04 CLI 辅助审查与成果交付 | OpenCode 审查指定改动，学生决定是否采纳，Terminal 复测、归档并提交 | 经审查批准的补丁、复核说明与交付文档 | 审查记录、采纳/拒绝理由、复测报告、可重现成果包 |

每课时建议采用 5 分钟导入、8 分钟概念与示范、25 分钟操作、7 分钟检查与提交。四课时内不要求学生从零搭建 UI 框架、编写鉴权系统或部署 K8S。

第四课时的 OpenCode 首轮先只分析指定文件并提出建议。修改代码前由学生确认，修改后必须运行测试。归档由 `export.sh` 执行，AI 仅辅助整理交付说明。学生不得以“AI 说通过了”代替运行证据。

## 八 Agent 手册与验证规则

每个实训步骤包含目标、要修改的文件、操作提示、预期现象、验证命令、常见错误和快捷提问。复用当前支持的 `file_exists`、`service_running`、`command_output` 和 `custom` 验证类型。

检查示例包括项目文件存在、8000 端口可访问、健康接口返回正确结构、请求构造测试通过、校验器正确拒绝反例、模型请求日志具有平台签发的请求 ID，以及成果包具有必需文件且不含凭证。

不能只检查学生可修改的 `passed=true` 报告。课堂检查使用教师维护的固定版本测试，并结合服务实际响应和平台请求记录；正式评分再由教师检查代码、证据和复核说明。学生可见样例用于学习，另保留教师侧检查样例。

## 十 验收与实施顺序

第一步完成可独立运行的教师参考项目与学生骨架，提供固定样例和检查脚本。第二步完成课程镜像、共享目录初始化及五个入口的同项目绑定。第三步实现模型网关并分别验收案例后端、OpenCode 与右侧 Agent。第四步编写四课时手册与作业，在课程草稿中绑定素材和模板。最后使用真实学生账号走通并发布试教。

端到端验收必须证明：

1. WebIDE 修改的文件在主容器可见，Terminal 构建后的界面在 Desktop 可观察。
2. Desktop 能处理成功、必填缺失、模型失败、非法 JSON 和校验失败，重试不丢输入。
3. CLI 实际在课程项目中审查，能看到最新代码；重连仍对应本会话项目。
4. 右侧 Agent 保持当前步骤上下文，验证器真实执行并记录失败与重试。
5. 实验对照记录真实模型、有效参数、响应及来源，不把样例当在线生成结果。
6. 普通回答和流式回答均验证，模型不可用时不得判为课程主链路完成。
7. 两个学生的文件与记录隔离，课时切换不会意外覆盖代码；退出和回收前能保存成果。
8. 学生提交成果后教师能查看、退回、评分和发布反馈。

当前共享节点约 2 核、8 GiB，优先预构建前端、预装依赖并使用外部模型推理。先验收单个工作区，再验证两个并发工作区；不能按账号数量承诺课堂并发。大模型权重部署和 GPU 推理优化不属于本课程首期范围。

## 十一 实训镜像评估与建设规格

### 11.1 本轮实际检查结果

2026-11-23 对运行中的 `lab-session-303` 进行只读检查：主容器使用 `docker.io/library/opencode-lab:latest`，IDE 使用 `gitpod/openvscode-server:latest`。主容器已有 Node 18.20.8、npm 10.8.2、Python 3.10.12，以及 Firefox、tmux、OpenCode。FastAPI、Uvicorn、httpx 和 jsonschema 可导入，pytest 未安装。WebIDE 用户 UID/GID 为 1000，当前共享目录权限为 777。

这些结论仅证明当前运行镜像的上述基础工具存在，不证明已经安装课程前端依赖、存在工作台项目或完成 OpenCode 的课程模型接入。镜像标签均为 latest，正式课程必须换成可追溯的固定版本或 digest。

本地构建脚本还包含多门旧课程、桌面版 VS Code、额外 AI 框架和 `COPY opencode-config/auth.json`。新课程不直接复制这套全量构建，也不假设线上镜像与本地未提交 Dockerfile 完全一致。

### 11.2 推荐镜像组合

保留“一名学生一个 Pod，主容器加 WebIDE 容器，共享一个 workspace 卷”的现有架构，不新增每学生数据库或第三个常驻课程服务容器。

| 镜像 | 职责 | 处理方式 |
|---|---|---|
| 提示词工作台课程主镜像 | 桌面、浏览器、Terminal、OpenCode、课程前后端运行及检查 | 新建课程专用镜像，复用经验证且无凭证的桌面构建方案 |
| OpenVSCode Server 镜像 | 文件编辑与前端开发辅助 | 优先复用已验收版本并固定 digest；不再安装另一套完整课程运行环境 |

主镜像可在构建上分为稳定基础镜像和课程增量层，这不会增加运行容器数。基础层负责桌面、工具链与服务管理；课程层负责锁定依赖、学生骨架、样例、构建产物和初始化脚本。为保持构建可复现，基础镜像、Node/Python/OpenCode 及项目依赖均需固定版本，并按最终项目兼容性测试选择工具链版本，不自动继承旧 Node 18 的选择。

新基础镜像必须从无凭证来源构建；若旧镜像层已经包含密钥，不能用子镜像中的删除命令视为完成脱敏。

### 11.3 主镜像内容

必需内容为轻量桌面与 Firefox、VNC/noVNC、tmux、Git、curl、Node/npm、Python 虚拟环境、FastAPI/Uvicorn/httpx/jsonschema/pytest、OpenCode，以及课程所需的前端依赖。

首期不加入 GPU 模型权重、Docker daemon、完整 K8S、另一个桌面 VS Code 或无关课程的大型框架。共享集群仍由平台管理，学生代码只运行在自己的 Lab。

源码模板存于 `/opt/courses/prompt-workbench`，Python 依赖存于 `/opt/venvs/prompt-workbench`，固定前端依赖可放于独立的 `/opt/course-deps` 并通过明确的初始化方式供项目使用。`/workspace/prompt-workbench` 是学生可编辑副本；不要在构建时仅把项目 COPY 到 `/workspace`，K8S 的 emptyDir 挂载会遮住镜像内该目录内容。

学生镜像包含可启动的学生骨架、公开样例和学习用检查脚本。教师完整参考实现与正式评分用检查集单独保管，不因学生镜像方便而一起交付。

### 11.4 初始化与进程生命周期

1. 检查共享卷与课程版本；仅在项目尚未初始化时复制模板，不覆盖学生现有代码。
2. 对齐 WebIDE UID/GID 1000 的共享文件读写权限，课程运行进程使用兼容身份或组权限；不依赖全目录 777。现有桌面启动方式若需要 root，则将桌面服务启动和课程进程身份分开验收。
3. 启动桌面/noVNC 与课程服务，由明确的进程管理器或等效机制收集日志、传递退出信号并支持重启；不只依靠 `tail -f /dev/null` 判断环境健康。
4. 课程服务监听 8000，提供前端静态页面和 API；Desktop 提供打开工作台的快捷入口。
5. Terminal 与 OpenCode 打开 `/workspace/prompt-workbench`。同一会话断线重连不能重新初始化项目，也不能因复用 tmux 而进入另一课程目录。
6. 镜像可在无模型连接时启动和编辑，界面明确显示模型不可用；真实模型任务仍需联网验收，不能通过离线样例绕过验收。

共享卷在 Pod 删除后丢失，不会因为更换镜像方案而自动持久化。启动脚本不能声称支持跨会话恢复；成果导出和作业提交必须纳入课时要求。

### 11.5 端口及模型配置

- noVNC 保留 6080；WebIDE 保留 3000；课程应用采用 8000。
- 可选开发模式使用 5173，避免与 WebIDE 端口冲突；课堂常规运行优先单服务提供构建产物。
- Kimi 等供应商密钥不写入 Dockerfile、镜像层、启动脚本、课程 `.env` 或共享项目。只在运行时配置受限教学网关地址和短时凭证，OpenCode 使用独立且不被成果导出包含的运行配置目录。
- 平台右侧 Agent 的模型配置与课程程序/OpenCode 的调用链路分别验证，不能从其中一个成功推断另外两个已接通。

### 11.6 构建发布与验收

在本地构建机或 CI 构建 Linux amd64 镜像，推送到可用镜像仓库；K8S 节点只预拉取，不在当前 2 核、8 GiB 的教学节点上执行全量构建。课程更新使用新版本，保留上一个版本用于回滚，不覆盖已运行学生会话的镜像或共享目录。

镜像门禁至少验证：首次与重复初始化、WebIDE/主容器双向文件可见与可写、前端重新构建后 Desktop 效果变化、课程 API 健康和错误响应、Terminal 检查命令、OpenCode 目录/工具调用/断线恢复、无凭证泄漏的成果导出，以及 Pod 停止后的清理。新课程镜像和新模板先绑定课程草稿，不直接修改现有所有课程的模板。

先用一个工作区测实际内存、CPU、启动时间和交互响应，再评估两个并发。镜像压缩体积和容器内存消耗不是同一指标；是否能同时授课必须以运行测试为准。
