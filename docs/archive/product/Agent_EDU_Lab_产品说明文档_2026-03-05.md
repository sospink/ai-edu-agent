## 1. 产品概述

### 一句话定义

**Agent EDU Lab** 是一个面向 AI 智能体开发方向的**教育实训平台**，将课程学习、云端实验环境、AI 教师辅助和项目实战整合为统一闭环，帮助学生从「看懂」真正走向「做到」。

### 产品背景

当前 AI 教育市场存在明显痛点：

- **传统 LMS** 解决内容分发，但无法保证实践能力的养成
- **在线视频课程** 停留在观看层面，缺乏动手练习路径
- **本地实验环境** 门槛高，配置复杂，大量学生卡在入门阶段
- **AI 辅助** 大多是独立聊天框，与教学流程割裂

Agent EDU Lab 针对以上问题进行了整体性产品设计，将「学—练—评—复盘」四个教学环节打通，构建真正可执行的 AI 人才培养路径。

### 适用方向

- AI 智能体开发（Agent Development）
- Prompt Engineering
- Dify / MCP 工具链开发
- 多 Agent 协作系统

## 2. 产品定位与核心价值

### 与传统平台的本质差异

| 对比维度 | 传统 LMS / 在线教育 | Agent EDU Lab |
|--------|------------------|---------------|
| 核心目标 | 知识传递与内容分发 | **能力养成与实战落地** |
| 学习方式 | 看视频、做练习题 | 理论学习 + 云端实操 + 项目实战 |
| AI 角色 | 无 / 推荐系统 | **课程感知教学 Agent，全程介入** |
| 环境准备 | 学生自行配置本地环境 | **云端一键拉起，零配置立即开始** |
| 评估方式 | 考试与作业 | 步骤验证 + 项目产出 |
| 扩展性 | 内容库为主，较封闭 | 课程、模型、工具均可持续扩展 |

### 三类用户价值

#### 对学生
- **降低入门门槛**：不需要先花大量时间配置本地开发环境
- **提升完成率**：有 AI 教师步骤引导和即时反馈，不容易中途卡死放弃
- **强化就业能力**：从「会知识点」升级到「能独立完成工程任务」

#### 对教师
- **降低带教压力**：AI 助教承担大量重复性答疑工作，教师聚焦核心辅导
- **教学更可控**：课程结构化、阶段化，便于组织和管理课堂
- **可持续复用**：课程内容与实训脚本可持续迭代，不必每次从头设计

#### 对院校 / 培训机构
- **缩短课程上线周期**：平台化能力开箱即用，显著降低基础设施建设成本
- **标准化实训能力**：统一实训环境标准，便于规模化推广部署
- **内容生态可扩展**：课程、项目、工具接入可持续新增，不受平台封闭限制

### 3.3 学习中心（Study Center）

**路由：** `/study`

**功能定位：** 课程浏览与学习入口，提供结构化的技能学习路径

**核心功能：**

- **技能列表（SkillList）：** 展示平台已发布课程，按方向和难度分层
- **技能详情（SkillDetail）：** 展示某一课程的完整阶段 → 课时结构
- **学习进度：** 登录态用户可记录学习进度，支持断点续学
- **课时类型分区：** 明确区分理论课与实训课，分别进入对应页面

**设计逻辑：**

```
技能列表 → 选择课程 → 技能详情（阶段结构）→ 选择课时 → 理论课 / 实训课
```

每门课程清晰展示：
- 技能方向与难度定级
- 阶段数量与课时数量
- 学习目标描述
- 当前学习进度（已登录）

### 3.4 理论课（Lesson Page）

**路由：** `/lesson/:id`

**功能定位：** 知识内容学习 + AI 动态讲解，是理论学习的核心场景

**关键能力：**

#### 多格式资料统一渲染
支持以下教学资料格式在同一界面统一阅读：
- **Markdown** — 结构化图文内容
- **PDF** — 上传的课程讲义
- **Word（.docx）** — 格式化文档资料

#### AI 智能讲解助教（右侧 Dify 嵌入）
- 嵌入方式：通过 iframe 嵌入 Dify Chatbot，浮层右侧展示
- **关键特性：课时级上下文驱动**
  - AI 助教根据当前课程 ID、课时 ID 动态生成开场讲解
  - 不同课时有不同的 AI 引入内容，而非固定通用话术
  - 学生提问时，AI 围绕当前课程内容精准回答，而不是泛泛回答
- 可现场演示：提一个与当前课时相关的问题，验证上下文感知能力

**产品意图：** 理论课不是「电子书阅读器」，而是「有 AI 陪伴的主动学习场景」。AI 助教感知当前课时，是平台 Agent 化教学理念的第一个落地点。

### 3.5 实训环境（Lab Page）

**路由：** `/lab`

**功能定位：** 云端实操核心场景，是平台最核心的差异化能力

#### 云端实验环境
- **一键启动**：点击即可拉起完整云端工作区，无需任何本地配置
- **环境一致性**：所有学生使用相同的预配置环境，避免「在我这里能跑」问题
- **可复用性**：课程实训脚本复用相同基础环境，降低维护成本

#### 多标签工作区协同

| 标签 | 用途 |
|-----|------|
| **Desktop** | 图形桌面操作，可运行 GUI 应用 |
| **Terminal** | 命令行终端，直接执行命令 |
| **IDE** | 在线代码编辑器，支持完整开发体验 |
| **CLI / OpenClaw / Gateway** | 按课程或项目模式动态切换 |

#### AI 教师实训引导模式
这是 AI 教师最核心的能力体现：

- **步骤化引导**：AI 教师按课程实训步骤逐步引导学生完成操作
- **结果验证**：AI 教师可检查学生的操作执行情况，判断步骤是否完成
- **进度推进**：验证通过后推进到下一步，形成有闭环的学习流程
- **不只是提示**：与普通聊天助手的本质区别在于「有状态、有步骤、有验证」

**产品意图：** 这是平台「教学 Agent + 实训环境深度联动」理念最直接的体现。不是「AI 在旁边聊天，学生自己操作」，而是「AI 引导操作，AI 验证结果，AI 推进进度」。


**与课程的关系：** 课程教知识，项目教迁移。课程完成后，学生在项目模块里把学到的能力应用到真实工程场景，形成可展示的项目经验。

## 4. AI Agent 教学概念设计

### 4.1 平台 AI 教学理念

Agent EDU Lab 将 AI 角色设计为「教学 Agent」而非「聊天机器人」，区别在于：

| 维度 | 普通 AI 聊天助手 | Agent EDU Lab AI 教师 |
|-----|--------------|----------------------|
| 感知范围 | 无上下文 | 感知当前课程、课时、实训步骤 |
| 交互模式 | 问答式 | 主动引导 + 被动答疑 |
| 行为边界 | 泛化回答 | 聚焦当前教学内容 |
| 状态管理 | 无记忆 | 有步骤状态与进度记录 |
| 教学介入 | 不介入操作 | 可验证操作结果，推进进度 |

### 4.2 AI 教师双模式

#### 模式一：全局聊天模式
- **入口：** 全局悬浮 Agent Widget
- **能力：** 基于平台知识库的问答，课程内容解释，学习建议
- **适用场景：** 课前预习、课后复习、跨课程提问

#### 模式二：实训引导模式
- **入口：** 实训页面（Lab Page）内嵌 AI 教师面板
- **能力：** 步骤化操作引导、执行结果检查、进度状态推进
- **适用场景：** 课时实训过程中的全程引导

### 4.3 课时上下文驱动机制（Dify 集成）

这是平台 AI 设计最核心的创新之一：

```
用户进入课时页面
    ↓
前端获取当前 课程ID + 课时ID + 用户信息
    ↓
向 Dify API 传递上下文参数（conversation_inputs）
    ↓
Dify 工作流根据上下文生成「课时专属开场内容」
    ↓
右侧助教面板展示动态开场，而非通用欢迎语
    ↓
学生提问时，AI 围绕该课时内容精准回答
```

**配置项（环境变量）：**
- `VITE_DIFY_BASE_URL` — Dify 服务地址
- `VITE_DIFY_CHATBOT_TOKEN` — Chatbot 访问 Token

**演示验证方式：** 进入不同课时，观察右侧 AI 助教开场内容是否不同，向 AI 提问课时相关内容，验证其准确性。

## 6. 用户角色与使用流程

### 6.1 用户角色

| 角色 | 权限范围 | 典型行为 |
|-----|---------|---------|
| **学生（Student）** | 浏览课程、完成实训、参与项目 | 学习、提问、做项目 |
| **教师（Teacher）** | 管理课程内容、查看学情数据 | 发布课程、查看进度 |
| **管理员（Admin）** | 平台全功能 + 用户管理 | 系统配置、数据管理 |

### 6.2 学生标准使用流程

```
1. 首页了解平台 → 注册 / 登录
2. 学习中心 → 选择技能方向（如：Dify 实战）
3. 技能详情 → 查看课程结构 → 进入第一个课时
4. 理论课 → 阅读资料 + AI 讲解助手互动
5. 实训课 → 启动云端环境 → AI 教师逐步引导
6. 完成所有课时 → 进入项目实战
7. 项目实战 → 按单元完成工程任务
8. 形成项目经验 → 个人中心查看学习档案
```

### 6.3 新用户上手路径（向导引导）

```
进入首页 → 左下角向导图标 → 向导 Hub 打开 →
选择「开始向导」 → 了解功能地图 →
「开始探索」→ 学习中心 → 选课开始
```

整体上手时间目标：**3 分钟内完成导航并开始第一门课程**

## 8. 核心功能交互逻辑

### 8.1 实训环境启动流程

```
用户点击「启动实训」
    ↓
检查登录状态 → 未登录则跳转 /login
    ↓
发送启动请求到后端（EDU_Backend）
    ↓
后端调用容器编排服务
    ↓
分配云端工作区实例
    ↓
前端获取连接信息（WebSocket / iFrame URL）
    ↓
多标签工作区展示（Desktop / Terminal / IDE / CLI）
```

### 8.2 AI 教师步骤验证流程

```
AI 教师展示当前步骤说明
    ↓
学生在 Terminal / IDE 执行操作
    ↓
学生点击「已完成」或 AI 主动检查
    ↓
AI 教师通过指定接口验证执行结果
    ↓
验证通过 → 步骤标记完成，展示下一步
验证失败 → 给出具体反馈，引导重试
    ↓
所有步骤完成 → 课时标记完成，更新进度
```

### 8.3 Dify 助教上下文传递

```javascript
// 理论课页面进入时触发
const context = {
  course_id: currentCourseId,
  lesson_id: currentLessonId,
  user_id: currentUser?.id,
  lesson_title: currentLesson?.title,
```

## 10. 常见问题与产品问答

### Q1：这和普通 LMS 有什么不同？

**A：** 普通 LMS（Learning Management System）主要解决内容管理和分发问题，学生在上面「看课、做题、考试」。Agent EDU Lab 解决的是「能力养成」问题，核心差异在于：
- 有**云端实训环境**，学生真正动手操作而不只是看
- 有**AI 教学 Agent**，主动介入教学过程而不只是答疑
- 有**项目实战模块**，学完能做真实工程任务

### Q2：AI 教师只是聊天机器人吗？

**A：** 不是。普通 AI 聊天框只能被动回答问题，与教学流程完全割裂。Agent EDU Lab 的 AI 教师具备：
- **上下文感知**：知道学生在哪个课时、学到哪一步
- **主动引导**：按步骤推进实训，不等学生发问
- **结果验证**：能判断学生的操作是否正确
- **状态记录**：记录哪些步骤已完成

### Q3：平台支持多少人同时使用？

**A：** 云端实训环境按需弹性扩展，平台设计目标是支持中大型班级教学场景（数十至数百并发）。具体容量取决于部署配置。

### Q4：课程内容可以自定义吗？

**A：** 可以。平台支持通过管理后台发布和管理课程，教师可以添加理论资料（Markdown/PDF/Word）和配置实训步骤。课程手册遵循标准格式规范，可持续迭代。

### Q5：平台是否可以私有化部署？

**A：** 平台架构支持私有化部署，前端（EDU_Frontend）和后端（EDU_Backend）均可独立部署。

### Q6：使用平台需要什么基础？

**A：** 面向学生端，平台通过云端环境消除了技术配置门槛，学生只需有浏览器即可开始学习。平台内置向导系统帮助零基础用户快速上手。
