# 功能开发计划模板 / 闭环检查清单

本模板用于约束后续功能开发，避免出现“只做展示 / 只做 GET / 只做新增就宣称完成”的伪 100% 情况。

使用规则：
- 先列闭环，再实现
- 先判断层级，再拆 TODO
- 若未覆盖该层级最小闭环项，最终汇报不得使用“已完成”表述
- 二阶段教学平台升级默认按 `L3 业务子系统` 处理，必须参考 [PHASE-2-TEACHING-PLATFORM-UPGRADE.md](PHASE-2-TEACHING-PLATFORM-UPGRADE.md) 拆成教师端 / 学生端 / 管理端 / 后端 / 权限 / 状态 / 验收闭环
- 涉及前端页面 / 组件时必须参考 [EDU_Frontend/DESIGN.md](../EDU_Frontend/DESIGN.md)，保持项目 UI 规范与三端视觉边界

## 9. 验收标准
### L1 组件验收
- 数据已接通
- 交互真实可用
- `loading / empty / error` 完整
- 没有假按钮、假弹窗、假状态

### L2 页面验收
- 读链路完整
- 至少一条主要写链路完整
- 搜索 / 筛选 / 刷新可用
- 组件联动正常
- 状态反馈完整
- 完成一轮页面冒烟

### L3 模块验收
- 主流程端到端可走通
- 关联页面 / 接口 / 权限 / 清理 / 异常路径已纳入范围
- 有明确模块级验收标准
- 有明确未完成项

## 11. 最终汇报措辞检查
如果本轮只完成了以下任一情况：
- 只有展示，没有主要写操作
- 只有读链路，没有关键交互
- 只有页面骨架，没有状态覆盖
- 只有单页，没有上下游闭环

则最终只能使用以下措辞：
- 已完成首版骨架
- 已打通读链路
- 已完成页面展示层
- 仍缺编辑 / 删除 / 交互闭环

只有当本层级最小闭环已满足时，才能使用：
- 该功能已完成
- 该页面已完成
- 该模块已完成
