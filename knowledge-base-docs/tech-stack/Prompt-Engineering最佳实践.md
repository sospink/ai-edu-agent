# Prompt Engineering 提示词工程最佳实践

## 课程定位

本课程讲授的是**提示词工程（Prompt Engineering）**，核心理念是将提示词从"一次性写法"升级为**可维护、可测试、可迭代的工程体系**。

> 核心转变：从"写提示词"到"构建提示词系统"

---

## 五大工程化原则

提示词工程化有五个核心原则，简称 **MPVTO**：

### 原则一：模块化（Modularity）

将提示词拆分为独立的功能模块，每个模块只负责一件事。

**为什么需要模块化？**
- 避免"上帝提示词"（一个提示词包含所有逻辑）
- 模块可以独立修改和测试
- 提高复用性

**模块化结构示例：**
```
[角色定义模块]
你是一个专业的XX助手...

[任务说明模块]
你的任务是...

[约束条件模块]
请遵守以下规则：
1. ...
2. ...

[输出格式模块]
请按以下格式输出：
...
```

**实战案例：万能文案生成器**

万能文案生成器将提示词拆分为：
- 角色模块：文案专家角色定义
- 平台模块：小红书/微博/公众号等不同平台规则
- 风格模块：活泼/专业/走心等风格定义
- 产品模块：产品信息注入
- 输出模块：字数/格式/表情要求

---

### 原则二：参数化（Parameterization）

将提示词中会变化的部分抽象为**参数变量**，固定不变的部分作为模板。

**参数化的好处：**
- 一个模板，多种用途
- 修改内容只需改参数，不需改模板
- 方便批量生成

**参数化示例：**
```
# 模板（固定部分）
你是一位专业的{platform}平台文案专家，
请为{product_name}撰写一篇{style}风格的推广文案。
字数要求：{word_count}字以内。

# 参数（可变部分）
platform: 小红书
product_name: 智能咖啡机
style: 活泼可爱
word_count: 200
```

**万能文案生成器的参数设计：**
- `{{platform}}`：目标平台
- `{{product}}`：产品名称
- `{{feature}}`：核心卖点
- `{{audience}}`：目标受众
- `{{tone}}`：文案风格

---

### 原则三：版本化（Versioning）

像管理代码一样管理提示词，记录每次修改的原因和效果。

**为什么需要版本化？**
- 提示词优化是反复迭代的过程
- 需要知道哪个版本效果最好
- 出现问题时可以回滚

**版本记录格式：**
```
# Prompt v1.0
日期：2024-01-01
修改说明：初始版本
测试结果：输出格式不稳定

# Prompt v1.1
日期：2024-01-05
修改说明：增加输出格式约束
测试结果：格式稳定，但风格偏正式

# Prompt v1.2
日期：2024-01-10
修改说明：调整风格描述词
测试结果：✅ 达到预期效果
```

**版本化最佳实践：**
- 每次修改前备份当前版本
- 记录修改原因（问题描述）
- 记录测试结果（是否解决问题）
- 给重要版本打标签（如 v2.0-stable）

---

### 原则四：可测试性（Testability）

为提示词设计测试用例，确保在各种输入下都能得到预期输出。

**测试用例设计原则：**
1. **正向用例**：标准输入，验证基本功能
2. **边界用例**：极端输入，验证鲁棒性
3. **负向用例**：异常输入，验证错误处理

**万能文案生成器测试矩阵：**

| 测试场景 | 平台 | 产品 | 风格 | 预期输出 |
|---------|------|------|------|---------|
| 正向基础 | 小红书 | 咖啡机 | 活泼 | 200字以内，含emoji |
| 边界测试 | 小红书 | 复杂工业产品 | 活泼 | 能简化专业术语 |
| 跨平台测试 | 微博 | 咖啡机 | 活泼 | 符合微博字数限制 |
| 风格切换 | 小红书 | 咖啡机 | 专业 | 无emoji，正式语气 |

**评估维度：**
- 相关性：内容是否切题
- 准确性：信息是否正确
- 格式合规：是否符合平台规范
- 风格匹配：是否符合要求的风格

---

### 原则五：可观测性（Observability）

在提示词执行过程中记录中间状态，方便调试和优化。

**为什么需要可观测性？**
- 当输出不理想时，能快速定位是哪个环节出了问题
- 监控提示词在生产环境的运行情况
- 收集数据用于持续优化

**可观测性的三个层次：**

**层次1：输入/输出日志**
```
[输入] platform=小红书, product=咖啡机, style=活泼
[输出] 早安打工人☕️今天被这款智能咖啡机治愈了...
[耗时] 1.2s
[Token] prompt=245, completion=186
```

**层次2：中间推理过程（思维链）**
```
[分析] 目标平台：小红书，受众以年轻女性为主
[分析] 产品特点：智能、便捷、生活品质提升
[策略] 采用"情感共鸣+产品功能"的写法
[生成] 开始撰写文案...
```

**层次3：质量评分**
```
[质量评估]
- 字数合规：✅ (186字，限制200字)
- 含emoji：✅ (3个)
- 产品信息：✅ (提到核心功能)
- 整体评分：4.2/5.0
```

## 万能文案生成器：综合案例

本课程的核心实战项目，综合运用五大工程化原则。

### 系统架构

```
用户输入
    ↓
[参数解析模块] 提取 platform/product/style 等参数
    ↓
[平台规则模块] 加载对应平台的规则约束
    ↓
[风格模板模块] 加载对应风格的写作指导
    ↓
[生成模块] LLM 生成文案
    ↓
[质量检验模块] 验证格式和内容合规性
    ↓
输出文案
```

### 支持的平台和风格

**平台：** 小红书、微博、微信公众号、抖音、LinkedIn

**风格：** 活泼可爱、专业权威、走心感人、幽默搞笑、极简高冷

### 核心 Prompt 模板（v2.0）

```
## 角色
你是一位精通各大社交媒体平台的资深文案策划师，
有10年品牌营销经验，深度了解{platform}平台的内容规则和用户喜好。

## 任务
为{product}撰写一篇{platform}平台的推广文案。

## 产品信息
- 产品名称：{product}
- 核心卖点：{features}
- 目标受众：{audience}

## 平台规范（{platform}）
{platform_rules}

## 风格要求
{style_guide}

## 输出格式
请直接输出文案内容，不要加任何解释。
```

## 常见错误与解决方案

### 错误1：提示词过长却效果差
**原因：** 没有做模块化，把所有要求堆在一起
**解决：** 按功能拆分模块，保持每个模块职责单一

### 错误2：换个产品就失效
**原因：** 没有做参数化，产品信息硬编码在提示词里
**解决：** 将变化的部分抽象为参数

### 错误3：无法追溯好版本
**原因：** 没有做版本化，随意修改
**解决：** 建立版本记录，每次修改留档

### 错误4：输出质量不稳定
**原因：** 没有做可测试性设计，靠感觉判断好坏
**解决：** 建立测试用例集，量化评估

### 错误5：出问题不知道原因
**原因：** 没有可观测性，黑盒运行
**解决：** 添加日志记录和质量评分

---

## 总结

提示词工程化 = **模块化** + **参数化** + **版本化** + **可测试** + **可观测**

好的提示词系统应该像好的软件工程一样：**可维护、可扩展、可测试、可监控**。

从"写提示词"到"构建提示词系统"，这是每个 AI 应用开发者必须完成的思维跃迁。
