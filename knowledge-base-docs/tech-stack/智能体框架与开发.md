# 智能体框架与开发

## 课程定位

本课程讲授**智能体（Agent）框架与开发**，基于 **LangChain / LangGraph** 框架和 **GLM-4** 模型，从理论到实践构建真正能"思考和行动"的 AI 智能体。

---

## 什么是 Agent（智能体）？

Agent 是一种能够**感知环境、做出决策、采取行动**的 AI 系统。与普通 LLM 对话不同，Agent 具备自主性——它可以调用工具、访问记忆、拆解复杂任务。

**普通 LLM 与 Agent 的区别：**

| 维度 | 普通 LLM | Agent |
|------|---------|-------|
| 能力 | 文本生成 | 感知+决策+行动 |
| 工具 | 无 | 可调用外部工具 |
| 记忆 | 无（或仅对话窗口） | 短期+长期记忆 |
| 自主性 | 被动响应 | 主动规划执行 |
| 任务复杂度 | 单轮简单任务 | 多步骤复杂任务 |

---

## PRA 循环：Agent 的核心运作机制

Agent 的工作方式可以用 **PRA 循环**描述：

```
感知（Perception）→ 推理（Reasoning）→ 行动（Action）→ 循环
```

### 感知（Perception）
Agent 接收来自环境的信息：
- 用户的文字输入
- 工具执行后的结果
- 记忆系统中的历史信息
- 外部 API 的返回数据

### 推理（Reasoning）
Agent 基于感知到的信息进行决策：
- 理解用户意图
- 制定执行计划
- 选择合适的工具
- 判断任务是否完成

### 行动（Action）
Agent 执行决策：
- 调用工具（搜索、计算、写文件等）
- 生成回复
- 更新记忆

PRA 循环会持续进行，直到任务完成。

---

## ReAct 模式：推理与行动的结合

**ReAct = Reasoning（推理）+ Acting（行动）**

ReAct 是目前最主流的 Agent 工作模式，核心思想是让 Agent 在行动前先"思考"，并在观察结果后再次"思考"。

**ReAct 执行流程：**

```
用户问题：帮我查一下北京今天的天气，并给出穿衣建议

思考（Thought）：我需要先获取北京的实时天气信息
行动（Action）：调用天气查询工具，参数：{"city": "北京"}
观察（Observation）：{"temp": "15-25°C", "weather": "晴", "wind": "微风"}

思考（Thought）：已获取天气，现在可以给出穿衣建议
行动（Action）：生成穿衣建议
观察（Observation）：建议生成完成

最终回答：今天北京天气晴，气温15-25°C，建议穿长袖衬衫或薄外套...
```

**ReAct 的优势：**
- 推理过程透明可见（可解释性）
- 错误发生时容易定位问题
- 可以根据观察结果动态调整策略

## 工具调用（Tool Calling）机制

工具是 Agent 与外部世界交互的桥梁。

### 工具的定义

在 LangChain 中定义工具：

```python
from langchain.tools import tool

@tool
def get_weather(city: str) -> str:
    """获取指定城市的天气信息。

    Args:
        city: 城市名称，如"北京"、"上海"
    Returns:
        天气信息字符串
    """
    # 调用天气 API
    result = weather_api.query(city)
    return f"{city}今日天气：{result['weather']}，气温{result['temp']}"

@tool
def search_web(query: str) -> str:
    """搜索互联网获取信息。

    Args:
        query: 搜索关键词
    Returns:
        搜索结果摘要
    """
    return web_search(query)
```

### 工具调用流程

```
1. LLM 分析用户需求
2. LLM 决定调用哪个工具，以及传入什么参数
3. 系统执行工具调用
4. 将工具返回结果传回 LLM
5. LLM 继续推理或生成最终回答
```

### 工具设计原则
- **职责单一**：每个工具只做一件事
- **描述清晰**：文档字符串要准确描述功能和参数
- **错误处理**：工具应该处理异常并返回友好的错误信息
- **返回值规范**：返回字符串，LLM 更容易理解

## 记忆系统（Memory System）

Agent 的记忆系统分为四种类型：

### 1. 短期记忆（Short-term Memory）
- **存储内容**：当前对话的上下文
- **实现方式**：对话历史列表（conversation_history）
- **特点**：会话结束后消失
- **用途**：维持对话连贯性

### 2. 长期记忆（Long-term Memory）
- **存储内容**：用户偏好、历史信息、重要事实
- **实现方式**：数据库（SQLite、PostgreSQL）
- **特点**：持久化存储，跨会话保留
- **用途**：记住用户，提供个性化服务

### 3. 工作记忆（Working Memory）
- **存储内容**：当前任务的中间状态
- **实现方式**：任务状态字典
- **特点**：任务执行期间使用
- **用途**：多步骤任务中保存中间结果

### 4. 语义记忆（Semantic Memory）
- **存储内容**：知识、概念、关系
- **实现方式**：向量数据库（结合 Embedding）
- **特点**：支持语义相似度检索
- **用途**：知识检索、RAG 场景

## LangChain vs LangGraph

### LangChain：线性链式调用
适合简单的、步骤固定的任务。

```python
from langchain.chains import LLMChain
from langchain.prompts import PromptTemplate
from langchain_community.chat_models import ChatZhipuAI

# 创建 LLM
llm = ChatZhipuAI(model="glm-4", temperature=0.7)

# 创建 Chain
prompt = PromptTemplate(
    template="你是一个助手，请回答：{question}",
    input_variables=["question"]
)

chain = LLMChain(llm=llm, prompt=prompt)
result = chain.run(question="什么是 Agent？")
```

### LangGraph：有状态的图结构
适合复杂的、需要条件分支和循环的 Agent。

```python
from langgraph.graph import StateGraph, END
from typing import TypedDict

# 定义状态
class AgentState(TypedDict):
    messages: list
    current_tool: str
    result: str

# 定义节点（每个节点是一个处理步骤）
def reasoning_node(state: AgentState) -> AgentState:
    """推理节点：决定下一步行动"""
    # LLM 推理
    ...
    return state

def tool_node(state: AgentState) -> AgentState:
    """工具执行节点"""
    # 执行工具调用
    ...
    return state

# 构建图
workflow = StateGraph(AgentState)
workflow.add_node("reasoning", reasoning_node)
workflow.add_node("tool", tool_node)

# 添加边（条件路由）
workflow.add_conditional_edges(
    "reasoning",
    lambda state: state["current_tool"] if state["current_tool"] else END,
    {"tool_name": "tool", END: END}
)
workflow.add_edge("tool", "reasoning")  # 工具执行后回到推理

workflow.set_entry_point("reasoning")
app = workflow.compile()
```

**选择建议：**
- 简单问答、固定流程 → LangChain Chain
- 复杂 Agent、需要循环决策 → LangGraph

## 单 Agent vs 多 Agent 系统（MAS）

### 单 Agent
一个 Agent 独立完成所有任务。

**适合场景：**
- 任务类型单一
- 逻辑相对简单
- 对延迟要求高

**实战项目：毒舌 Gordon（美食点评 Agent）**
- 角色：脾气暴躁但专业的美食评论家
- 能力：搜索餐厅信息、分析菜品、生成毒舌点评
- 工具：网络搜索、菜单解析

### 多 Agent 系统（MAS）

多个专门化的 Agent 协同完成复杂任务。

**架构模式：**

```
用户请求
    ↓
[协调者 Agent（Orchestrator）]
    ├── [研究员 Agent] → 负责信息收集
    ├── [分析师 Agent] → 负责数据分析
    └── [写作 Agent]  → 负责内容生成
```

**实战项目：创意风暴（多 Agent 头脑风暴系统）**

角色组成：
- **主持人 Agent**：负责协调讨论流程，整合各方观点
- **乐观派 Agent**：专门提出支持性观点和正面可能性
- **批判派 Agent**：专门提出质疑和风险分析
- **创意派 Agent**：专门提出创新和非常规想法

工作流程：
```
用户提出话题
    ↓
主持人拆解问题，分配给各 Agent
    ↓
各 Agent 独立分析，提交观点
    ↓
主持人整合所有观点，形成综合报告
```

**MAS 的优势：**
- 并行处理，效率更高
- 专业分工，质量更好
- 可扩展，容易增加新角色

## 常用 GLM-4 集成

本课程使用智谱 AI 的 **GLM-4** 作为基础模型：

```python
from langchain_community.chat_models import ChatZhipuAI

# 初始化 GLM-4
llm = ChatZhipuAI(
    model="glm-4",
    temperature=0.7,
    zhipuai_api_key="your-api-key"
)

# 带工具的 Agent
from langchain.agents import create_react_agent, AgentExecutor
from langchain import hub

# 加载 ReAct prompt
prompt = hub.pull("hwchase17/react")

# 创建 Agent
agent = create_react_agent(llm, tools=[get_weather, search_web], prompt=prompt)
agent_executor = AgentExecutor(agent=agent, tools=[get_weather, search_web], verbose=True)

# 运行
result = agent_executor.invoke({"input": "北京今天天气怎么样？"})
```

## 总结

Agent 开发的核心要素：
1. **PRA 循环**：感知-推理-行动，是 Agent 的基本运作方式
2. **ReAct 模式**：推理与行动交替进行，是主流实现方案
3. **工具调用**：连接 LLM 与外部世界的桥梁
4. **记忆系统**：短期/长期/工作/语义，赋予 Agent "记忆"
5. **框架选择**：简单任务用 LangChain Chain，复杂 Agent 用 LangGraph
6. **单/多 Agent**：根据任务复杂度选择架构
