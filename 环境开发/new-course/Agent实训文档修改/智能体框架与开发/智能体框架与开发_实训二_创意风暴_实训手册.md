## 步骤 1: 了解项目背景与学习目标

在实训一中，我们构建了"毒舌 Gordon"——一个具备工具调用和记忆能力的**单智能体**。但现实中，复杂任务往往需要多个角色分工协作，就像一场真正的头脑风暴会议：

- 需要**不同视角的创意者**从技术、商业、用户等维度提出方案
- 需要**严格的评审官**对方案进行客观评分筛选
- 需要**优化师**对优秀方案进行深化完善
- 需要**汇报员**将最终成果整理输出

这正是 **MAS（Multi-Agent System，多智能体系统）** 的核心场景。

### 学习目标

| 知识点 | 具体内容 |
|--------|----------|
| 多 Agent 协作模式 | Supervisor 监督者模式的设计与实现 |
| LangGraph 状态图 | StateGraph、Node、Edge、Conditional Edge |
| 角色化 Prompt 设计 | 为不同 Agent 编写差异化 System Prompt |
| 工作流编排 | 顺序执行、条件路由、循环迭代 |
| API 服务化 | FastAPI 封装 + 流式输出（SSE） |

## 步骤 5: 定义共享状态 state.py

> 💡 **核心概念**：State 是多 Agent 之间的"共享白板"，所有 Agent 通过读写 State 来协作。这是从单 Agent 到多 Agent 最关键的思维转变。

创建 `state.py`：

```python
"""
state.py - 共享状态定义模块
定义多 Agent 系统中流转的全局状态

设计说明：
1. State 是所有 Agent 的"数据契约"
2. 每个 Agent 读取 State 获取输入，写入 State 传递输出
3. 区分"过程数据"和"控制流"是良好的工程实践
"""

from typing import TypedDict, Annotated, List, Optional
from langgraph.graph.message import add_messages
from langchain_core.messages import BaseMessage


class IdeaItem(TypedDict):
    """单条创意数据结构"""
    id: str                    # 创意编号
    perspective: str           # 来源视角（技术/商业/用户）
    title: str                 # 创意标题
    description: str           # 创意描述
    score: Optional[float]     # 评审分数（0-10）
    feedback: Optional[str]    # 评审反馈


class BrainstormState(TypedDict):
    """
    创意风暴全局状态 - 所有 Agent 共享
    
    类比：这就像会议室的白板，
    每个参会者（Agent）都可以在上面写东西、看别人写的东西
    """
    
    # --- 输入 ---
    topic: str                                  # 创意主题
    requirements: str                           # 补充需求
    
    # --- 过程数据 ---
    messages: Annotated[list[BaseMessage], add_messages]  # 对话历史（自动累加）
    raw_ideas: List[IdeaItem]                   # 原始创意池
    evaluated_ideas: List[IdeaItem]             # 评审后的创意（含分数）
    refined_ideas: List[IdeaItem]               # 优化后的创意
    
    # --- 控制流 ---
    current_round: int                          # 当前轮次
    current_agent: str                          # 当前执行的 Agent
    
    # --- 输出 ---
    final_report: str                           # 最终报告


# 测试状态结构
if __name__ == "__main__":
    test_state = BrainstormState(
        topic="AI 驱动的个性化教育平台",
        requirements="面向高职院校学生",
        messages=[],
        raw_ideas=[],
        evaluated_ideas=[],
        refined_ideas=[],
        current_round=1,
        current_agent="",
        final_report="",
    )
    print("✅ 状态结构定义正确")
    print(f"主题: {test_state['topic']}")
```

## 步骤 6: 编写Agent公共工具函数

> 💡 **核心理解**：同一个 LLM，通过不同的 System Prompt 扮演不同角色——这就是多 Agent 的本质。就像同一个演员，换上不同的剧本就能演不同的角色。

创建 `agents.py`，首先实现公共工具函数：

```python
"""
agents.py - 多 Agent 定义模块
定义创意风暴系统中的所有 Agent 角色

Agent 角色设计说明：
1. 创意 Agent（×3）：从不同视角生成创意方案
2. 评审 Agent：对所有创意进行评分筛选
3. 优化 Agent：对 Top-K 创意进行深化完善
4. 汇报 Agent：生成最终的创意报告

每个 Agent 本质上是一个【System Prompt + LLM 调用 + 输出解析】的组合
"""

from zhipuai import ZhipuAI
from typing import List
from state import BrainstormState, IdeaItem
from config import Config
import json
import uuid


# ============================================================
# LLM 调用工具函数
# ============================================================

def call_llm(system_prompt: str, user_prompt: str, temperature: float = 0.7) -> str:
    """
    统一的 LLM 调用函数
    
    Args:
        system_prompt: 角色设定提示词
        user_prompt: 用户/任务提示词
        temperature: 温度参数（创意高、评审低）
    
    Returns:
        LLM 的文本回复
    """
    client = ZhipuAI(api_key=Config.ZHIPUAI_API_KEY)
    
    try:
        response = client.chat.completions.create(
            model=Config.MODEL_NAME,
            messages=[
                {"role": "system", "content": system_prompt},
                {"role": "user", "content": user_prompt},
            ],
            temperature=temperature,
            max_tokens=Config.MAX_TOKENS,
        )
        return response.choices[0].message.content
    except Exception as e:
        print(f"❌ LLM 调用失败: {e}")
        return f"[LLM 错误] {str(e)}"


def parse_json_from_llm(content: str) -> list:
    """
    从 LLM 输出中提取 JSON
    
    LLM 输出不总是规范的 JSON，需要做兜底处理
    """
    try:
        json_str = content
        if "```json" in content:
            json_str = content.split("```json")[1].split("```")[0]
        elif "```" in content:
            json_str = content.split("```")[1].split("```")[0]
        return json.loads(json_str.strip())
    except (json.JSONDecodeError, IndexError):
        return []
```

## 步骤 7: 编写创意Agent角色提示词与工厂函数

在 `agents.py` 中继续添加创意Agent的提示词和工厂函数：

```python
# ============================================================
# 创意 Agent - 角色提示词
# ============================================================

CREATIVE_PROMPTS = {
    "技术可行性": """你是一位资深技术架构师，擅长从技术可行性角度思考创新方案。

你的思考维度：
- 现有技术栈能否支撑？需要哪些新技术？
- 技术实现的难度和周期如何？
- 是否有开源方案可以借鉴？
- 技术风险点在哪里？

请针对给定主题，提出 2-3 个具有技术创新性的创意方案。""",

    "商业价值": """你是一位敏锐的商业分析师，擅长从市场和商业价值角度评估创新机会。

你的思考维度：
- 目标用户群体是谁？市场规模多大？
- 商业模式是什么？如何变现？
- 竞品分析：有没有类似产品？差异化在哪？
- 投入产出比如何？

请针对给定主题，提出 2-3 个具有商业潜力的创意方案。""",

    "用户体验": """你是一位用户体验设计专家，擅长从终端用户的真实需求出发思考产品创新。

你的思考维度：
- 用户的核心痛点是什么？
- 使用场景是怎样的？
- 交互体验如何降低使用门槛？
- 用户的情感需求是什么？

请针对给定主题，提出 2-3 个以用户为中心的创意方案。""",
}

CREATIVE_OUTPUT_FORMAT = """
请严格按照以下 JSON 格式输出（不要输出其他内容）：

```json
[
  {
    "title": "创意标题",
    "description": "详细描述（100-200字）"
  }
]
```
"""


# ============================================================
# 创意 Agent 节点函数（工厂模式）
# ============================================================

def create_creative_node(perspective: str):
    """
    工厂函数：为指定视角创建创意 Agent 节点
    
    设计模式说明：
    使用闭包捕获 perspective 参数，避免为每个视角写重复代码
    这和实训一中的单 Agent 不同——这里是"同一模板，不同角色"
    """
    
    def creative_node(state: BrainstormState) -> dict:
        print(f"  💡 [{perspective}] 创意 Agent 开始工作...")
        
        system_prompt = CREATIVE_PROMPTS[perspective] + CREATIVE_OUTPUT_FORMAT
        
        # 构造任务上下文
        context = f"创意主题：{state['topic']}\n补充需求：{state['requirements']}"
        
        # 如果不是第一轮，加入上轮评审反馈作为参考
        if state.get("evaluated_ideas"):
            top_ideas = [i for i in state["evaluated_ideas"] if (i.get("score") or 0) >= 7]
            if top_ideas:
                context += "\n\n上轮高分创意供参考（请在此基础上发散新思路，不要重复）：\n"
                for idea in top_ideas:
                    context += f"- {idea['title']}（{idea.get('score', 'N/A')}分）\n"
        
        # 调用 LLM
        response = call_llm(system_prompt, context, Config.CREATIVE_TEMPERATURE)
        
        # 解析输出为结构化创意
        parsed = parse_json_from_llm(response)
        new_ideas = []
        for item in parsed:
            new_ideas.append(IdeaItem(
                id=str(uuid.uuid4())[:8],
                perspective=perspective,
                title=item.get("title", "未命名创意"),
                description=item.get("description", ""),
                score=None,
                feedback=None,
            ))
        
        # 解析失败的兜底
        if not new_ideas:
            new_ideas.append(IdeaItem(
                id=str(uuid.uuid4())[:8],
                perspective=perspective,
                title=f"[解析失败] {perspective}视角创意",
                description=response[:500],
                score=None,
                feedback=None,
            ))
        
        # 追加到创意池（注意是追加，不是覆盖）
        existing = state.get("raw_ideas", [])
        
        print(f"  ✅ [{perspective}] 产出 {len(new_ideas)} 条创意")
        
        return {
            "raw_ideas": existing + new_ideas,
            "current_agent": f"creative_{perspective}",
        }
    
    return creative_node


# 创建三个视角的创意节点
tech_creative_node = create_creative_node("技术可行性")
biz_creative_node = create_creative_node("商业价值")
ux_creative_node = create_creative_node("用户体验")
```

## 步骤 8: 编写评审Agent

在 `agents.py` 中继续添加：

```python
# ============================================================
# 评审 Agent
# ============================================================

CRITIC_SYSTEM_PROMPT = """你是一位严格但公正的创意评审专家。你的任务是对每一条创意方案进行评分和点评。

评分维度（每项 1-10 分，取平均）：
1. **创新性**：方案是否有新意？是否区别于常见做法？
2. **可行性**：以当前技术和资源，能否在6个月内落地？
3. **影响力**：如果成功实施，能带来多大的价值？
4. **完整性**：方案描述是否清晰、逻辑是否自洽？

请严格按照以下 JSON 格式输出评审结果：

```json
[
  {
    "id": "创意的原始id",
    "score": 8.5,
    "feedback": "简要点评（50字以内）"
  }
]
```

注意：评分要有区分度，不要都给高分或都给低分。feedback 要具体指出优点或不足。
"""


def critic_node(state: BrainstormState) -> dict:
    """
    评审 Agent 节点：对所有原始创意评分
    
    类比：这是头脑风暴会议中的"评委环节"
    评审需要高确定性，所以 temperature 设为 0.3
    """
    print("  📝 评审 Agent 开始工作...")
    
    raw_ideas = state.get("raw_ideas", [])
    if not raw_ideas:
        return {"evaluated_ideas": [], "current_agent": "critic"}
    
    # 构造评审输入
    ideas_text = ""
    for idea in raw_ideas:
        ideas_text += f"\n--- 创意 {idea['id']} [{idea['perspective']}视角] ---\n"
        ideas_text += f"标题：{idea['title']}\n"
        ideas_text += f"描述：{idea['description']}\n"
    
    user_prompt = f"创意主题：{state['topic']}\n\n以下是待评审的创意方案：\n{ideas_text}"
    
    response = call_llm(CRITIC_SYSTEM_PROMPT, user_prompt, Config.CRITIC_TEMPERATURE)
    
    # 解析评审结果并合并到创意中
    scores_list = parse_json_from_llm(response)
    scores_map = {item["id"]: item for item in scores_list} if scores_list else {}
    
    evaluated = []
    for idea in raw_ideas:
        score_info = scores_map.get(idea["id"], {})
        evaluated.append(IdeaItem(
            id=idea["id"],
            perspective=idea["perspective"],
            title=idea["title"],
            description=idea["description"],
            score=score_info.get("score", 5.0),
            feedback=score_info.get("feedback", "评审数据解析失败，给予默认分数"),
        ))
    
    # 按分数降序排列
    evaluated.sort(key=lambda x: x.get("score") or 0, reverse=True)
    
    print(f"  ✅ 评审完成，最高分 {evaluated[0].get('score', '?')} 分")
    
    return {
        "evaluated_ideas": evaluated,
        "current_agent": "critic",
    }
```

## 步骤 9: 编写优化Agent

```python
# ============================================================
# 优化 Agent
# ============================================================

REFINER_SYSTEM_PROMPT = """你是一位资深产品优化专家。你的任务是对已通过评审的优秀创意进行深化完善。

对每个创意，你需要：
1. **补充方案细节**：将概念级描述扩展为可执行的方案
2. **融合多视角优势**：如果不同视角有互补的创意，尝试融合
3. **预判风险**：指出潜在问题和应对策略
4. **明确下一步**：给出具体的 MVP（最小可行产品）建议

请严格按照以下 JSON 格式输出：

```json
[
  {
    "id": "原始创意id",
    "title": "优化后的标题",
    "description": "深化后的方案描述（200-400字）",
    "risks": "主要风险与应对（100字以内）",
    "mvp_plan": "MVP建议（100字以内）"
  }
]
```
"""


def refiner_node(state: BrainstormState) -> dict:
    """
    优化 Agent 节点：对 Top-K 创意进行深化
    
    类比：会议中的"方案深化环节"，从创意变为可执行方案
    """
    print("  ✨ 优化 Agent 开始工作...")
    
    evaluated = state.get("evaluated_ideas", [])
    top_ideas = evaluated[:Config.TOP_K_IDEAS]
    
    if not top_ideas:
        return {"refined_ideas": [], "current_agent": "refiner"}
    
    ideas_text = ""
    for idea in top_ideas:
        ideas_text += f"\n--- {idea['id']} [{idea['perspective']}] 评分：{idea.get('score', 'N/A')} ---\n"
        ideas_text += f"标题：{idea['title']}\n"
        ideas_text += f"描述：{idea['description']}\n"
        ideas_text += f"评审反馈：{idea.get('feedback', '无')}\n"
    
    user_prompt = f"创意主题：{state['topic']}\n\n以下是通过评审的 Top 创意：\n{ideas_text}"
    
    response = call_llm(REFINER_SYSTEM_PROMPT, user_prompt, Config.REFINER_TEMPERATURE)
    
    # 解析优化结果
    parsed = parse_json_from_llm(response)
    refined = []
    if parsed:
        for item in parsed:
            original = next((i for i in top_ideas if i["id"] == item.get("id")), {})
            refined.append({
                **original,
                "title": item.get("title", original.get("title", "")),
                "description": item.get("description", original.get("description", "")),
                "risks": item.get("risks", ""),
                "mvp_plan": item.get("mvp_plan", ""),
            })
    else:
        refined = top_ideas  # 解析失败则返回原始创意
    
    print(f"  ✅ 优化了 {len(refined)} 条创意")
    
    return {
        "refined_ideas": refined,
        "current_agent": "refiner",
    }
```

## 步骤 12: 编写工作流编排 workflow.py —— 构建状态图

```python
# ============================================================
# 构建工作流图
# ============================================================

def build_brainstorm_graph():
    """
    构建创意风暴工作流图
    
    流程：
    START → [创意生成×3] → 评审 → (循环 or 优化) → 汇报 → END
    
    ┌──────────────────────────────────────────┐
    │           创意风暴工作流                    │
    ├──────────────────────────────────────────┤
    │  [START]                                 │
    │     │                                    │
    │     ▼                                    │
    │  [creative_tech] ──→ [creative_biz]      │
    │                          │               │
    │                          ▼               │
    │                    [creative_ux]          │
    │                          │               │
    │                          ▼               │
    │                      [critic]            │
    │                       ╱    ╲             │
    │          round < max ╱      ╲ else       │
    │                    ╱          ╲           │
    │           [next_round]    [refiner]       │
    │               │               │          │
    │               └──→ loop      ▼           │
    │                         [reporter]       │
    │                              │           │
    │                              ▼           │
    │                            [END]         │
    └──────────────────────────────────────────┘
    """
    
    # 1. 创建 StateGraph，传入状态类型
    graph = StateGraph(BrainstormState)
    
    # 2. 添加所有节点（每个 Agent 是一个节点）
    graph.add_node("creative_tech", tech_creative_node)
    graph.add_node("creative_biz", biz_creative_node)
    graph.add_node("creative_ux", ux_creative_node)
    graph.add_node("critic", critic_node)
    graph.add_node("refiner", refiner_node)
    graph.add_node("reporter", reporter_node)
    graph.add_node("next_round", next_round_node)
    
    # 3. 设置入口点
    graph.set_entry_point("creative_tech")
    
    # 4. 添加固定边（确定性流转）
    graph.add_edge("creative_tech", "creative_biz")     # 技术 → 商业
    graph.add_edge("creative_biz", "creative_ux")       # 商业 → 用户体验
    graph.add_edge("creative_ux", "critic")             # 用户体验 → 评审
    
    # 5. 添加条件边（Supervisor 决策点！）
    #    这是多 Agent 系统的灵魂 —— 动态路由
    graph.add_conditional_edges(
        "critic",  # 从评审节点出发
        lambda state: "next_round"
            if state.get("current_round", 1) < Config.MAX_BRAINSTORM_ROUNDS
            else "refiner",
        {
            "next_round": "next_round",  # 还有轮次 → 继续
            "refiner": "refiner",        # 轮次用完 → 优化
        }
    )
    
    # 6. 循环回路：新一轮从技术创意开始
    graph.add_edge("next_round", "creative_tech")
    
    # 7. 收尾流程
    graph.add_edge("refiner", "reporter")   # 优化 → 汇报
    graph.add_edge("reporter", END)         # 汇报 → 结束
    
    # 8. 编译图（从定义态变为可执行态）
    compiled = graph.compile()
    
    return compiled


# 测试工作流构建
if __name__ == "__main__":
    graph = build_brainstorm_graph()
    print("✅ 工作流图构建成功")
    print(f"节点列表: {list(graph.get_graph().nodes.keys())}")
```

"""
server.py - FastAPI 服务模块
将多 Agent 工作流暴露为 RESTful API

1. 前端/其他系统可以调用
2. 支持并发请求
3. 支持流式输出（SSE），实时观察每个 Agent 的工作进度

from fastapi import FastAPI, HTTPException
from fastapi.responses import StreamingResponse
from pydantic import BaseModel, Field
from workflow import build_brainstorm_graph
import json
import asyncio


app = FastAPI(
    title="🧠 创意风暴 MAS API",
    description="基于 LangGraph 的多 Agent 创意风暴系统",
    version="1.0.0",
)

# 编译工作流（应用启动时只编译一次，避免重复开销）
brainstorm_graph = build_brainstorm_graph()


# ============================================================
# 请求/响应模型
# ============================================================

class BrainstormRequest(BaseModel):
    """创意风暴请求"""
    topic: str = Field(..., description="创意主题", examples=["AI驱动的个性化教育平台"])
    requirements: str = Field(default="", description="补充需求", examples=["面向K12学生"])


class BrainstormResponse(BaseModel):
    """创意风暴响应"""
    topic: str
    total_ideas: int
    top_ideas: list
    final_report: str


# ============================================================
# API 端点
# ============================================================

@app.post("/brainstorm", response_model=BrainstormResponse)
async def run_brainstorm(request: BrainstormRequest):
    """
    启动一次完整的创意风暴（同步）
    """
    initial_state = {
        "topic": request.topic,
        "requirements": request.requirements,
        "messages": [],
        "raw_ideas": [],
        "evaluated_ideas": [],
        "refined_ideas": [],
        "current_round": 1,
        "current_agent": "",
        "final_report": "",
    }
    
    try:
        final_state = await asyncio.to_thread(
            brainstorm_graph.invoke, initial_state
        )
        
        return BrainstormResponse(
            topic=request.topic,
            total_ideas=len(final_state.get("raw_ideas", [])),
            top_ideas=final_state.get("refined_ideas", [])[:5],
            final_report=final_state.get("final_report", "生成失败"),
        )
    except Exception as e:
        raise HTTPException(status_code=500, detail=f"创意风暴执行失败: {str(e)}")


@app.post("/brainstorm/stream")
async def run_brainstorm_stream(request: BrainstormRequest):
    """
    流式执行创意风暴（SSE）
    
    每个 Agent 执行完成后推送一条事件，前端可实时展示进度
    """
    initial_state = {
        "topic": request.topic,
        "requirements": request.requirements,
        "messages": [],
        "raw_ideas": [],
        "evaluated_ideas": [],
        "refined_ideas": [],
        "current_round": 1,
        "current_agent": "",
        "final_report": "",
    }
    
    async def event_generator():
        try:
            for event in brainstorm_graph.stream(initial_state):
                for node_name, node_output in event.items():
                    summary = _summarize(node_name, node_output)
                    data = json.dumps(
                        {"agent": node_name, "status": "completed", "summary": summary},
                        ensure_ascii=False,
                    )
                    yield f"data: {data}\n\n"
            
            yield f"data: {json.dumps({'agent': 'system', 'status': 'finished'}, ensure_ascii=False)}\n\n"
        except Exception as e:
            yield f"data: {json.dumps({'agent': 'system', 'status': 'error', 'detail': str(e)}, ensure_ascii=False)}\n\n"
    
    return StreamingResponse(event_generator(), media_type="text/event-stream")


def _summarize(node_name: str, output: dict) -> str:
    """为流式输出生成简要摘要"""
    if "raw_ideas" in output:
        return f"生成了 {len(output['raw_ideas'])} 条创意"
    elif "evaluated_ideas" in output:
        ideas = output["evaluated_ideas"]
        avg = sum(i.get("score", 0) for i in ideas) / max(len(ideas), 1)
        return f"评审完成，平均分 {avg:.1f}"
    elif "refined_ideas" in output:
        return f"优化了 {len(output['refined_ideas'])} 条创意"
    elif "final_report" in output:
        return "报告生成完成"
    return "执行中..."


@app.get("/health")
async def health_check():
    """健康检查"""
    return {"status": "ok", "service": "brainstorm-mas"}
```

## 步骤 17: 理解多Agent协作架构

### 多 Agent 协作流程

```
          用户输入创意主题
               │
               ▼
      ┌─────────────────┐
      │   Supervisor     │ ◄── 隐式监督者：通过条件路由实现
      │  （工作流本身）    │
      └────────┬────────┘
               │ 分配任务
        ┌──────┼──────┐
        ▼      ▼      ▼
    ┌──────┐┌──────┐┌──────┐
    │🔧技术││💰商业││🎨用户│ ◄── 创意 Agent ×3（同模板不同 Prompt）
    └──┬───┘└──┬───┘└──┬───┘
       └───────┼───────┘
               ▼
      ┌─────────────────┐
      │   📝 评审 Agent  │ ◄── 打分筛选（temperature=0.3）
      └────────┬────────┘
            ╱     ╲
      轮次<max    轮次=max
          │          │
     [🔄再来一轮]  [✨ 优化 Agent]
                     │
                     ▼
               [📊 汇报 Agent]
                     │
                     ▼
                最终创意报告
```

### 对比实训一：ReAct vs Supervisor

```
实训一：ReAct 模式（单 Agent）

  用户输入 → Thought → Action → Observation → ... → Final Answer
  
  特点：单个 Agent 自己决定何时用工具、何时回答
  类比：一个人独自完成任务


实训二：Supervisor 模式（多 Agent）

  用户输入 → Agent_A → Agent_B → Agent_C → [条件判断] → Agent_D → 输出
  
  特点：多个 Agent 按流程协作，由工作流（Supervisor）控制流转
  类比：一个团队按流程协作完成任务
```

## 步骤 18: 掌握LangGraph核心API

### LangGraph 核心 API 速查

```python
from langgraph.graph import StateGraph, END

# === 创建图 ===
graph = StateGraph(MyState)              # 传入状态类型

# === 添加节点 ===
graph.add_node("name", function)         # function(state) -> dict

# === 添加边 ===
graph.add_edge("A", "B")                 # 固定边：A 完成后一定去 B
graph.add_conditional_edges(             # 条件边：根据状态动态路由
    "A",                                 # 起始节点
    route_function,                      # 路由函数：state -> str
    {"option_a": "B", "option_b": "C"}   # 映射表
)

# === 入口与编译 ===
graph.set_entry_point("first_node")      # 设置起始节点
compiled = graph.compile()               # 编译为可执行图

# === 执行 ===
result = compiled.invoke(initial_state)  # 同步执行，返回最终状态
for event in compiled.stream(state):     # 流式执行，逐步输出
    print(event)
```

### 常见问题排查

| 问题 | 可能原因 | 解决方案 |
|------|---------|---------|
| `JSONDecodeError` | LLM 输出不规范 | 检查 Prompt 中的格式指令，或使用 `parse_json_from_llm` 兜底 |
| Agent 执行超时 | API 响应慢 | 增大 `LLM_TIMEOUT` 或使用更快的模型 |
| 创意重复度高 | temperature 过低 | 调高 `CREATIVE_TEMPERATURE`，优化轮次间的上下文传递 |
| 评分缺乏区分度 | Prompt 约束不足 | 在评审 Prompt 中强调"必须有高有低" |
| `ImportError` | 依赖版本不兼容 | 使用 `python3 -m pip install -r /root/MultiAgentFramework/brainstorm-mas/requirements.txt` 统一版本 |
| 流式接口无输出 | SSE 格式问题 | 确保每条数据以 `data: ` 开头，以 `\n\n` 结尾 |
