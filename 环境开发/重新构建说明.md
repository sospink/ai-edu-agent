# 重新构建镜像说明

## 为什么要重新构建？

重新构建镜像可以将所有课程文件和脚本**永久打包**进镜像，避免每次创建容器都需要手动修复。

---

## 重新构建前 vs 重新构建后

| 项目 | 重新构建前 | 重新构建后 |
|------|-----------|-----------|
| **课程文件** | ❌ 缺少 `ade-skill/` | ✅ 完整包含 6 门课程 |
| **测试脚本** | ❌ 缺少 `test-courses-detailed.sh` | ✅ 完整包含所有测试脚本 |
| **API Keys** | ❌ 需要配置 | ❌ 仍需配置（安全原因） |
| **启动流程** | 3 步（修复+配置+测试） | 2 步（配置+测试） |
| **容器创建** | 需要手动修复 | 开箱即用 |

---

## 重新构建步骤

### 1. 停止并删除旧容器

```bash
# 查看容器名称
docker ps -a | grep lab

# 停止容器
docker stop <container-name>

# 删除容器
docker rm <container-name>
```

### 2. 删除旧镜像

```bash
# 查看镜像
docker images | grep opencode-lab-ai

# 删除旧镜像
docker rmi opencode-lab-ai:latest
```

### 3. 重新构建镜像

```bash
cd ~/work/course/环境开发

# 使用代理加速（推荐）
sudo docker build \
  --build-arg http_proxy=http://192.168.20.3:7890 \
  --build-arg https_proxy=http://192.168.20.3:7890 \
  -f Dockerfile.ai-courses-optimized \
  -t opencode-lab-ai:latest .

# 或不使用代理
sudo docker build \
  -f Dockerfile.ai-courses-optimized \
  -t opencode-lab-ai:latest .
```

**预计时间**: 10-20 分钟

### 4. 启动新容器

```bash
docker run -d \
  -p 2222:22 \
  -p 5901:5901 \
  -p 6080:6080 \
  --name ai-lab \
  opencode-lab-ai:latest
```

### 5. 配置 API Keys 并测试

```bash
cd ~/work/course/环境开发
sudo ./quick-start-rebuilt.sh
```

## 常见问题

### Q1: 重新构建会丢失数据吗？

A: 
- **镜像**: 不会，旧镜像会被新镜像替换
- **容器**: 会，需要删除旧容器并创建新容器
- **数据**: 如果使用了数据卷挂载（`-v`），数据不会丢失

### Q2: 重新构建后还需要运行 fix-missing-files.sh 吗？

A: **不需要**！所有文件已经在镜像中了。

### Q3: 重新构建后还需要配置 API Keys 吗？

A: **需要**！API Keys 不应该打包进镜像（安全原因），每次创建新容器后都需要配置。

### Q4: 如何保存 API Keys 配置？

A: 使用数据卷挂载 `/workspace` 目录：

```bash
docker run -d \
  -p 2222:22 -p 5901:5901 -p 6080:6080 \
  -v ~/ai-lab-workspace:/workspace \
  --name ai-lab \
  opencode-lab-ai:latest
```

这样 `.env` 文件会保存在宿主机的 `~/ai-lab-workspace/` 目录中。

### Q5: 重新构建需要多长时间？

A: 
- **首次构建**: 10-20 分钟（需要下载所有依赖）
- **再次构建**: 5-10 分钟（Docker 会使用缓存）
- **使用代理**: 可以加快下载速度

### Q6: 如何加速重新构建？

A: 使用代理：

```bash
sudo docker build \
  --build-arg http_proxy=http://192.168.20.3:7890 \
  --build-arg https_proxy=http://192.168.20.3:7890 \
  -f Dockerfile.ai-courses-optimized \
  -t opencode-lab-ai:latest .
```

## 推荐的工作流程

### 开发阶段（频繁修改）

使用快速修复脚本，无需重新构建：

```bash
# 修改课程文件后
sudo ./fix-missing-files.sh

# 配置 API
sudo ./setup-api-keys.sh

# 测试
sudo ./test-courses-quick.sh
```

### 生产部署（稳定版本）

重新构建镜像，确保所有文件都在镜像中：

```bash
# 重新构建
sudo docker build -f Dockerfile.ai-courses-optimized -t opencode-lab-ai:latest .

# 启动容器
docker run -d -p 2222:22 -p 5901:5901 -p 6080:6080 --name ai-lab opencode-lab-ai:latest

# 配置和测试
sudo ./quick-start-rebuilt.sh
```

## 总结

| 场景 | 推荐方案 | 原因 |
|------|---------|------|
| **开发测试** | 快速修复脚本 | 快速，无需等待构建 |
| **生产部署** | 重新构建镜像 | 稳定，所有文件永久包含 |
| **分发给学生** | 重新构建镜像 | 开箱即用，减少配置步骤 |
| **频繁修改课程** | 快速修复脚本 | 灵活，可以快速迭代 |

---

**建议**: 
- 开发阶段使用快速修复
- 确认所有课程都正常后，重新构建一个稳定版本
- 将稳定版本用于生产部署和学生使用
