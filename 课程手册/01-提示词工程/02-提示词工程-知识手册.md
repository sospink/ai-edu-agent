## 🎯 什么是提示词工程？

### 基本概念

**提示词（Prompt）** 是你发送给AI模型的指令或问题。提示词的质量直接决定了AI输出的质量。

**提示词工程** 是设计、优化和管理提示词的系统化方法，目标是让AI生成更准确、更可控、更有价值的内容。

### 为什么需要提示词工程？

1. **提高准确性**：精心设计的提示词能让AI更准确地理解你的需求
2. **增强可控性**：通过结构化的提示词，可以控制输出的格式和风格
3. **提升效率**：可复用的提示词模板能大幅提高工作效率
4. **保证质量**：系统化的方法能确保输出质量的稳定性

## 🏗️ 提示词工程五大原则

### 1. 模块化（Modularity）

将提示词拆分为可复用的模块，就像搭积木一样组合使用。

**优点**：
- 提高复用性
- 便于维护和更新
- 降低复杂度

**示例**：
```python
# 语气模块
TONE_MODULES = {
    "professional": "使用专业、正式的语气",
    "casual": "使用轻松、随意的语气",
    "humorous": "使用幽默、风趣的语气"
}

# 平台模块
PLATFORM_MODULES = {
    "xiaohongshu": "小红书风格：使用emoji、分段清晰",
    "weibo": "微博风格：简洁有力、话题标签"
}
```

### 2. 参数化（Parameterization）

通过参数控制提示词的行为，而不是硬编码。

**优点**：
- 灵活性高
- 易于调整
- 支持批量处理

**示例**：
```python
def build_prompt(topic, tone="professional", length=200):
    return f"""
    主题：{topic}
    语气：{tone}
    字数：约{length}字
    """
```

### 3. 版本化（Versioning）

为提示词添加版本号，追踪变更历史。

**优点**：
- 可追溯
- 便于回滚
- 支持A/B测试

**示例**：
```python
VERSION = "1.0.0"  # 主版本.次版本.修订号
```

### 4. 可测试（Testability）

设计可测试的提示词，验证输出质量。

**优点**：
- 质量保证
- 快速发现问题
- 支持自动化测试

**示例**：
```python
def test_prompt(prompt):
    result = call_ai(prompt)
    assert len(result) > 0
    assert "关键词" in result
```

### 5. 可观测（Observability）

记录提示词的使用情况和效果。

**优点**：
- 性能监控
- 问题诊断
- 持续优化

**示例**：
```python
metadata = {
    "version": "1.0.0",
    "timestamp": "2026-01-15",
    "model": "qwen3-max",
    "tokens": 150
}
```

## 💡 提示词设计技巧

### 1. 明确角色定位

告诉AI它扮演什么角色，这能显著提高输出质量。

```
你是一位专业的文案撰写专家，擅长创作吸引人的营销文案。
```

### 2. 提供清晰的任务描述

用简洁明确的语言描述你想要什么。

```
【任务】
为以下产品创作一篇小红书风格的推广文案。
```

### 3. 设定具体要求

列出明确的要求和限制条件。

```
【要求】
1. 字数：150-200字
2. 包含3个emoji
3. 突出产品的核心卖点
4. 语气轻松活泼
```

### 4. 指定输出格式

明确告诉AI你期望的输出格式。

```
【输出格式】
标题：[吸引人的标题]
正文：[文案内容]
标签：#标签1 #标签2
```

### 5. 提供示例

给出一两个示例，帮助AI理解你的期望。

```
【示例】
输入：智能手表
输出：⌚️ 这款智能手表太惊艳了！不仅颜值在线...
```

## 🔧 提示词工程化实践

### 1. 构建提示词库

创建一个提示词模板库，包含常用的提示词模块。

```python
class PromptLibrary:
    def __init__(self):
        self.templates = {}
        self.modules = {}
    
    def add_template(self, name, template):
        self.templates[name] = template
    
    def get_template(self, name):
        return self.templates.get(name)
```

### 2. 实现提示词组合

支持灵活组合不同的提示词模块。

```python
def combine_prompts(*modules):
    return "\n\n".join(modules)
```

### 3. 添加错误处理

处理API调用失败、超时等异常情况。

```python
try:
    result = call_ai(prompt)
except TimeoutError:
    result = "请求超时，请重试"
except APIError as e:
    result = f"API错误：{e}"
```

### 4. 实现缓存机制

对相同的提示词缓存结果，提高效率。

```python
cache = {}

def get_result(prompt):
    if prompt in cache:
        return cache[prompt]
    
    result = call_ai(prompt)
    cache[prompt] = result
    return result
```

## 📊 提示词评估标准

### 1. 准确性（Accuracy）

输出是否符合预期，是否包含必要信息。

### 2. 相关性（Relevance）

输出是否与主题相关，是否偏离主题。

### 3. 完整性（Completeness）

输出是否完整，是否遗漏重要信息。

### 4. 一致性（Consistency）

多次运行是否产生一致的结果。

### 5. 效率（Efficiency）

生成结果所需的时间和token数量。

## ⚠️ 常见陷阱与注意事项

### 1. 避免模糊指令

❌ 错误：写一篇好文章  
✅ 正确：写一篇800字的科技产品评测文章，重点介绍功能和性价比

### 2. 不要过度复杂

❌ 错误：在提示词中包含过多的条件和限制  
✅ 正确：保持提示词简洁明了，必要时分步骤执行

### 3. 注意上下文长度

- 大多数模型有token限制
- 过长的提示词可能被截断
- 合理控制提示词长度

### 4. 测试不同模型

- 不同模型对提示词的理解可能不同
- 针对特定模型优化提示词
- 保持提示词的通用性

## 🚀 进阶技巧

### 1. Chain of Thought（思维链）

引导AI逐步思考，提高复杂任务的准确性。

```
让我们一步步思考：
1. 首先分析问题的核心
2. 然后列出可能的解决方案
3. 最后选择最佳方案
```

### 2. Few-Shot Learning（少样本学习）

提供几个示例，帮助AI理解任务。

```
示例1：输入A → 输出B
示例2：输入C → 输出D
现在处理：输入E → ?
```

### 3. Role Playing（角色扮演）

让AI扮演特定角色，提高输出质量。

```
你是一位资深的产品经理，请从用户体验的角度分析...
```

### 4. Self-Consistency（自我一致性）

多次运行相同提示词，选择最一致的结果。
